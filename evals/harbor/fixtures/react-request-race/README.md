# React request race fixture

This evaluator-owned fixture adapts the documented interleaving in [react-select issue #4645](https://github.com/JedWatson/react-select/issues/4645): a cached query, another pending query, returning to the cached query, then the pending response arriving late. The upstream comparison point is [useAsync.ts at a92c09a836450cbb849f3a90eade18e1320cb651](https://github.com/JedWatson/react-select/blob/a92c09a836450cbb849f3a90eade18e1320cb651/packages/react-select/src/useAsync.ts#L167-L190).

The inventory adapter, warehouse-local identity cache, components and failure/retry requirements here are newly written synthetic code. They extend that failure mechanism into a multi-file repair and do not reproduce upstream source or claim to be the original issue's exact repository state. The evaluator includes the cached-query interleaving as well as out-of-order successes/rejections, a response while the current request remains pending, warehouse changes, normalized cache hits, same-ID entity isolation, empty results and retry behavior.

Only `environment/` enters the task build context. Hidden interaction tests and the independent solution remain outside it. `tests/grade.py` copies final `src/` into a fresh directory, uses evaluator-owned configuration and `/opt/fixture-deps`, and writes `/logs/verifier/checks.json` and `reward.txt`. Public happy-path tests and TypeScript/Vite builds pass before repair; deterministic deferred-response assertions fail before repair and pass after the oracle. jsdom assertions are distinct from separate Chromium browser calibration.
