# Inventory CSV handoff

This synthetic React app displays one server page at a time and exports inventory from a paginated adapter. Users report missing records and malformed CSV, especially when they keep working while an export is loading. Display pagination and export traversal share an adapter but must have independent state.

Clicking `Export CSV` captures the current search text and selected IDs once. With no selection, export all records matching that search. With a selection, export only selected IDs encountered in those matching server pages, preserving server order rather than click order. The captured inputs apply to every page even if search or selection changes while the export is pending. Each click starts a fresh traversal at the first page: the first export must contain the just-fetched data and later exports must use that click's current inputs and responses, not an earlier export's data. Keep the export button disabled while one export is running; users may still change search, selection and screen pages.

Follow the adapter's opaque `nextCursor` until it is null, even when a page is empty or shorter than `pageSize`. An ID may repeat at a page boundary; export it once, retaining the first occurrence and the order in which distinct IDs first appeared. Never replace or append to the table's visible rows, count, selection or current screen page as a side effect of export. User-initiated screen changes during export still work normally.

Create one UTF-8 CSV download, named `inventory.csv`, only after all pages succeed. Keep the `id,name,note` header and CRLF record separators, including the final separator. Preserve field values exactly, including leading-zero IDs. CSV fields containing commas, double quotes, CR or LF must be double-quoted, and embedded double quotes doubled; do not coerce IDs to numbers or add spreadsheet formulas. Empty exports still contain the header. If any page fails, no download or success message is allowed; show `Export failed. Try again.`, restore the export button, and let another click retry from the first page. A successful retry clears the error.

Run `npm run test:one -- tests/App.test.tsx` and `npm run build`. Tests use jsdom and do not prove browser rendering. This is a synthetic adaptation of common asynchronous export failures, not original upstream code or a claimed reproduction of a specific issue.
